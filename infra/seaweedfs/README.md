# Correctif de qualification SeaweedFS 4.51

Décision du développeur du 28 octobre 2026 : qualifier une correction de SeaweedFS avant de reprendre le raccordement de 7a. Ce dossier ne remplace pas le stockage du Compose et ne publie pas d'image dans un registre.

Source : SeaweedFS [4.51](https://github.com/seaweedfs/seaweedfs/tree/153ab668c99731a6d29492bf6c61d0b4fa701101), licence Apache-2.0. Archive, compilateur Go 1.26.8 et image de base sont épinglés par empreinte. Le patch garde le mécanisme amont de stockage des versions physiques ; il corrige la sélection des parties visibles par S3, dans le fournisseur et non par une déduplication opportuniste de l'adaptateur Memoria.

- `multipart.patch` modifie le listing et la sélection avant contrôle des ETag à la finalisation. Une erreur de lecture reste une erreur, pas une liste vide. Une collecte de métadonnées tronquée à la finalisation échoue fermée, au lieu de choisir une ancienne version faute d'avoir vu les suivantes.
- `memoria_multipart.go` choisit par timestamp de chunk, comme le finaliseur amont, avec départage déterministe et secours pour les parties inline. Les résultats sont triés par **numéro**, y compris 10 000, et paginés après sélection. Un retry ne consomme pas une place supplémentaire dans la page. Le listing garde au plus les 10 000 numéros S3 en mémoire, indépendamment des versions physiques ; lecture limitée à quinze secondes, retries transitoires avec collecteur neuf.
- Le checksum SHA-256 stocké d'une partie est rendu dans le listing ; le service garde néanmoins son plan signé et compare les reçus. La signature, le contrôle du checksum des octets, l'authentification S3 et l'isolation des buckets ne sont pas désactivés.
- `memoria_multipart_test.go` s'ajoute aux tests du package S3 amont. Les tests HTTP de Memoria restent indispensables : un helper testé ne qualifie pas le serveur.

Construire : `pnpm build:storage:fixture`. Node télécharge l'archive officielle si nécessaire, vérifie son SHA-256, crée un répertoire neuf dans `.local/seaweedfs-qualification`, puis lance `build.sh` dans un conteneur limité à 2 CPU / 3 Gio, CGO désactivé. Les tests complets du package `weed/s3api` doivent passer avant compilation et création de l'image locale. Aucun Go installé sur Windows n'est nécessaire. Le premier build télécharge les modules vérifiés par le `go.sum` amont ; les volumes Docker nommés `memoria-seaweed-go-mod` et `memoria-seaweed-go-build` servent de cache de compilation, pas de données métier. Prévoir plusieurs Gio de disque et plusieurs minutes au premier lancement ; ce coût de build n'est pas une mesure du service.

Le manifeste `.local/seaweedfs-qualification/manifest.json` contient le commit source, les empreintes des entrées, du binaire et de l'image. `pnpm test:storage --candidate` utilise l'ID immuable de cette image et refuse des sources de patch modifiées depuis le build. Sans `--candidate`, le banc conserve l'image amont 4.51 pour reproduire le défaut. Les journaux de la candidate sont distincts, dans `.local/storage-proof-candidate`.

Limites à conserver lors de la qualification : ce patch local n'est pas une correction publiée ou maintenue par l'amont. Il ne réécrit pas le stockage physique, ne prouve pas la récupération d'espace disque après les retries, ni une atomicité générale ListParts/UploadPart/Complete concurrente. Memoria doit conserver ses intentions et plans immuables, rapprocher les réponses ambiguës, refuser des versions devenues incompatibles et vérifier l'objet final avant publication. Les essais de concurrence, annulation et nettoyage du protocole précèdent l'ouverture des routes. Ne pas déclarer la session 7a terminée au seul passage du banc fournisseur.
