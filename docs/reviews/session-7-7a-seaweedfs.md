## Ce qui change et pourquoi

La recherche amont du 28 octobre n'a pas trouvé de version publiée plus récente que 4.51 ; le listing restait identique au commit amont `c2863d9a4f28eacd262fb5b83f1b7fca520abf0d`. Sources : [releases](https://github.com/seaweedfs/seaweedfs/releases), [code vérifié](https://github.com/seaweedfs/seaweedfs/blob/c2863d9a4f28eacd262fb5b83f1b7fca520abf0d/weed/s3api/filer_multipart.go). Le correctif part donc du tag 4.51, commit **`153ab668c99731a6d29492bf6c61d0b4fa701101`**.

Le fournisseur sélectionne désormais une seule version par numéro avant de paginer. Il utilise le timestamp de chunk déjà employé par son finaliseur, avec ordre déterministe en cas d'égalité et secours pour les parties inline. Le tri numérique corrige également le cas 1 000 / 10 000, dont l'ordre lexicographique faisait perdre une partie. Les retries n'ajoutent pas une ligne au résultat ; une lecture transitoirement échouée repart avec un collecteur neuf. La mémoire du collecteur est bornée par les 10 000 numéros S3, le temps de lecture par quinze secondes. Aucun corps d'objet n'est conservé dans ce collecteur.

La finalisation élimine les versions supersédées **avant** de comparer les ETag : une ancienne version ne redevient pas sélectionnable par un ancien reçu. Si la collecte de métadonnées existante est tronquée, le finaliseur échoue fermé au lieu de choisir sur une vue incomplète. Le checksum SHA-256 de la version choisie est rendu dans le listing. Le plan signé Memoria continue de faire autorité pour les numéros, tailles et checksums attendus ; signatures et validation des octets restent actives.

Pour MinIO, pas de patch : la configuration globale `MINIO_API_CORS_ALLOW_ORIGIN=https://localhost` est utilisée dans **un second conteneur jetable**, privé au port local 19000. Cette option est [documentée dans le code de la version locale](https://github.com/minio/minio/blob/RELEASE.2025-10-15T17-29-55Z/internal/config/api/api.go). Le test vérifie l'origine autorisée et l'absence d'autorisation pour `https://untrusted.invalid`. Aucun changement du MinIO applicatif au port 9000 ; le 501 du test historique par bucket reste reproductible.

## Guide manuel

1. Avec Docker, Node 24, pnpm, le `.env` local et l'image MinIO du projet construite, lancer **`pnpm build:storage:fixture`**. Première exécution : téléchargement des sources/modules, plusieurs minutes et plusieurs Gio de cache disque possibles. Le compilateur est limité à deux CPU et trois Gio ; aucune mesure de performance en parallèle.
2. Vérifier la fin de construction et le manifeste. Les tests Go doivent terminer par `PASS`. Un patch changé depuis le build entraîne ensuite un refus explicite du lanceur ; reconstruire, ne pas modifier le manifeste à la main.
3. Lancer **`pnpm test:storage --candidate`**. Attendre **23/23 sur chaque fournisseur** et code de sortie 0. Lire les deux rapports dans `.local/storage-proof-candidate` et vérifier les lignes de nettoyage. Les buckets, objets et conteneurs de test sont jetables, distincts des données applicatives.
4. Pour comparer, lancer **`pnpm test:storage`** : cette commande garde l'image officielle et la configuration MinIO historique, et doit encore échouer. Le journal explique les différences ; ce n'est pas un échec à ignorer dans la candidate.
5. Lire le diff du fournisseur avant toute future mise à jour : tester la version amont suivante, retirer ce patch seulement après passage des mêmes scénarios et des mesures applicatives. Aucun tag `latest` n'est utilisé pour SeaweedFS ou le compilateur.

## Ce qui pourrait casser

Une mise à jour amont peut changer les métadonnées de parties, l'ordre de sélection ou les transactions de finalisation. L'archive et le patch sont vérifiés, et les sources modifiées obligent un nouveau build testé. Ce fork local demande une maintenance ; il n'est pas couvert par une promesse de support amont. La collecte de finalisation amont reste bornée et peut refuser une accumulation extrême de versions physiques : pas de revendication de reprise illimitée, nettoyage et supervision à qualifier dans le cycle de vie 7a/7b.

La preuve ne remplace pas les contrôles métier : objets finaux immuables, droits et intentions revérifiés au commit, nettoyage concurrent et réponses S3 ambiguës restent obligatoires. Les tests navigateur derrière Caddy et les mesures de gros fichiers/collaboration restent à faire. Aucune API de fichiers ni interface ouverte dans cette correction ; **pas de clôture de 7a à ce stade**.
