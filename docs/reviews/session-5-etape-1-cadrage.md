## Inventaire prévisionnel des routes et quotas (R12)

Toutes passent par le guard global, identité/session injectées ; aucune exception `@Public()` n'est proposée. Les routes `/api/auth/organization/*` restent fermées. Origin/CSRF, méthodes exactes, corps stricts et bornés s'ajoutent aux quotas. ## Risques et limites à surveiller

- Le guard global exige déjà une authentification complète du compte. L'arrivée MFA doit passer par les routes de facteurs existantes, sans nouvelle exception permettant une session restreinte sur les pages.
- Les checks de statut d'invitation du plugin ne couvrent pas seuls le commit des effets métier. La preuve de rollback avec le vrai adaptateur est bloquante avant les écrans.
- Le résolveur collaboratif et le contrôle API sont encore owner/member. Un élargissement naïf de cette liste donnerait tout le workspace à guest. L'append recontrôle déjà edit, mais il faut lui fournir un niveau issu de vrais grants.
- Les droits changent avec les ancêtres et les déplacements. Un contrôle sur la seule page racine ou un filtrage après pagination peut manquer des descendants ou exposer des métadonnées.
- Invalidation distante impossible pour un navigateur entièrement hors ligne, exports irrévocables et tombstones locaux : R02/R07/R08 ne disparaissent pas avec cette session. Le travail refusé doit être signalé, jamais silencieusement rejoué.
- La résolution récursive peut coûter plus cher ; mesure alternée avec la nouvelle règle requise en 5d, sur secteur, plus profils guest. Pas de benchmark lancé dans ce cadrage.
- Les réserves de session 4 demeurent : R09 crashs, R11 pile dédiée/cinquante comptes, R13 RGPD, R14 cache réel après grâce avant utilisateurs ; R01/R03/R06 avant SaaS. Le scénario C03 peut couvrir R14, mais ne le clôt qu'après exécution documentée.

## Guide de relecture de cette étape

1. Vérifier la fusion #5 et le point de départ de branche ; comparer la branche à `main` : seuls documents/preuves changent.
2. Lire les sept décisions reçues et distinguer les valeurs encore proposées dans ADR 018. Valider ou corriger le cadrage complet avant 5a.
3. Parcourir un exemple : guest read sur A, edit sur A/B ; B est éditable, A ne l'est pas, C frère de A reste invisible. Un read ajouté sur B ne diminue pas un edit hérité. Un parent archivé masque tout son sous-arbre.
4. Vérifier le parcours d'arrivée : une invitation n'est ni une vérification d'email ni un facteur ; sous obligation, accepter puis enrôler ne suffit pas sans preuve forte.
5. Relire le retrait d'accès hors ligne et les guides futurs 5a–5d. Les fonctionnalités ne sont pas testables dans l'interface à cette étape.
6. Consulter le journal complet `pnpm check` de cette livraison. Ce contrôle du socle ne vaut pas exécution des scénarios futurs.
