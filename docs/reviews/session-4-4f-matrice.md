# Session 4f — matrice adverse et décisions

Cette matrice consolide 4a–4e et leurs limites. « Couvert » signifie que le scénario indiqué a été exécuté, pas qu'une classe entière d'attaques est impossible. Les journaux de la campagne courante sont référencés dans la [fiche 4f](session-4-4f-revue-adverse.md). **Aucun risque résiduel n'est marqué accepté.** Les recommandations ci-dessous ne sont pas des décisions du développeur.

## Index des preuves

- **A01–A08** : [attaques serveur](../../apps/api/src/adversarial.e2e.ts), `pnpm test:auth:adversarial` ; Nest compilé, Better Auth réel, PostgreSQL isolé, signatures P-256, sockets réseau. Fixtures SQL pour vérifier les emails et injecter des pannes ; aucune substitution du validateur de facteur.
- **B01–B03** : [attaques navigateur](../../scripts/test-auth-adversarial-browser.mjs), `pnpm test:auth:adversarial:browser` ; vrai HTTPS Caddy, Edge, IndexedDB et décisions HTTP. Le module de cache de production est compilé et chargé dans le navigateur pour contrôler exactement l'ordre des réponses ; l'interface complète est couverte séparément par le parcours 4e.
- **F** : [strong-auth.e2e.ts](../../apps/api/src/strong-auth.e2e.ts), `pnpm test:auth:strong`.
- **W** : [workspace-security.e2e.ts](../../apps/api/src/workspace-security.e2e.ts), `pnpm test:auth:workspace`.
- **R** : [recovery.e2e.ts](../../apps/api/src/recovery.e2e.ts), `pnpm test:auth:recovery`.
- **Q** : [rate-limits.e2e.ts](../../apps/api/src/rate-limits.e2e.ts), `pnpm test:auth:limits`.
- **C** : [cache-policy.e2e.ts](../../apps/api/src/cache-policy.e2e.ts), `pnpm test:auth:cache` ; **I** : [yjs-cache.test.ts](../../apps/web/src/lib/yjs-cache.test.ts), `pnpm check`.
- **BF/BR/BQ/BC** : scripts `test-auth-strong-browser.mjs`, `test-auth-recovery-browser.mjs`, `test-auth-limits-browser.mjs`, `test-auth-cache-browser.mjs` ; quatre parcours dans les builds réels derrière Caddy et Mailpit. Authentificateur virtuel avec UV pour l'automatisation ; matériel Android/Hello/YubiKey validé par le développeur en 4a, à reprendre dans le guide consolidé.

Les noms entre guillemets sont des fragments exacts du scénario, recherchables dans le fichier et le journal. L'[inventaire des 27 routes](session-4-4f-routes.md) complète cette matrice.

## Tableau final des risques résiduels — décisions du développeur requises

Toutes les décisions sont **en attente**. Les risques humains ou de disponibilité ne sont pas rendus acceptables automatiquement par un test passant. Toute modification de décision devra citer ce tableau, le périmètre et la date.

| Risque                                             | Conséquence / absence de test                                                                                     | Recommandation de l'agent                                                                                                                                                     | Décision   |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| R01 — huit places d'un compte occupées             | Victime non admise pendant une attaque soutenue ; attente bornée seulement après admission                        | Envisager tolérance explicite pour MVP de studio avec passkey/récupération disponibles ; file réservée par cookie d'appareil obligatoire avant SaaS                           | En attente |
| R02 — navigateur hors ligne ou suspendu            | Interdiction distante non reçue immédiatement ; contenu déjà en mémoire/disque inaccessible au serveur            | Tolérance explicite de la limite physique ; poste partagé/cache interdit pour données sensibles ; contrôle en ligne avant hydratation                                         | En attente |
| R03 — saturation globale                           | File, CPU/DB, réseau ou révocation sous charge non garantis ; absence de test d'attaque Internet                  | Réseau limité pour MVP ; protection en amont et qualification de charge obligatoires avant SaaS ; ne promettre aucun SLA de révocation sous saturation                        | En attente |
| R04 — ingénierie sociale de l'opérateur            | Exploitant convaincu de retirer le facteur d'une victime ; identité humaine non testable par logiciel             | Procédure en personne/visio, second membre si possible, aucun simple message ; accès opérateur restreint et audité                                                            | En attente |
| R05 — email au moins une fois et budget hostile    | Doublon si crash après SMTP ; quota destinataire épuisable ; SMTP production non testé                            | Tolérance explicite du doublon, jeton usage unique ; surveiller retries/abandons ; qualifier SMTP et sauvegarde/restauration avant usage réel                                 | En attente |
| R06 — timing sous attaque distribuée               | Réponses génériques mais différences temporelles possibles ; aucune campagne statistique Internet                 | Ne pas présenter les comptes comme indétectables ; campagne dédiée avant SaaS, revue de chaque nouveau parcours coûteux                                                       | En attente |
| R07 — exports/captures/mémoire                     | Impossible d'effacer les copies déjà exportées ou capturées par une personne autorisée                            | Documenter la portée exacte du cache ; politique humaine des postes et fichiers téléchargés ; aucun engagement DRM                                                            | En attente |
| R08 — tombstones et panne de stockage              | UUID/marqueurs locaux restent après logout pour bloquer les onglets anciens ; panne disque non simulée            | Conserver les tombstones sans contenu, nécessaires à la non-résurrection ; informer et demander fermeture des onglets/effacement des données du site si stockage indisponible | En attente |
| R09 — interruptions et concurrence non exhaustives | Rollbacks/courses ciblés testés ; pas de kill à chaque instruction, deadlocks exhaustifs ni tick minute attendu   | Ajouter essais de crash au déploiement ; conserver refus par défaut/transactions et alertes ; tolérance MVP seulement explicite                                               | En attente |

| R11 — capacité réelle studio                       | 50 logins simulés, pas 50 utilisateurs sur pile dédiée ; appareils physiques pas automatisés                      | Maintenir test 4 vCPU/8 Gio + 50 comptes avant premiers utilisateurs, avec guide matériel consolidé                                                                           | En attente |
| R12 — clés API/webhooks et futurs invités          | Gates testés par contrats, produits/routes invités pas encore livrés                                              | Exiger attaques end-to-end quand ces routes existent ; ne pas les déclarer sécurisées par anticipation                                                                        | En attente |
