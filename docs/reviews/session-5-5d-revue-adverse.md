# Session 5d — invalidations ciblées et revue adverse

Branche `codex/session-5-guests-sharing`, après validation manuelle de 5a, 5b et 5c. Cette fiche consolide les preuves de session 5. Aucune création ni fusion de PR par l'agent. Les décisions de risques appartiennent au développeur.

## Changement bloquant traité en premier

Un déplacement, archivage ou changement de partage n'interrompt plus indistinctement le studio. Le calcul des effets utilisé par l'aperçu détermine aussi les couples personne/page à invalider. Seule une variation effective `none/read/edit` modifie leur version. L'archivage d'une page retire aussi l'accès à ses descendants, sans toucher les autres pages.

La migration **0020** ajoute `page_access_state` et une file transactionnelle de réconciliation, vide après commit. Les triggers regroupent toutes les modifications d'une transaction ; les anciennes invalidations globales sont remplacées. La vérification serveur conserve session, assurance, politique, arbre et grants courants. Les notifications réveillent les contrôles, mais seules les connexions devenues invalides sont fermées. Le journal Yjs garde son verrou de page, sans prendre le verrou de workspace.

IndexedDB **v4** sépare les barrières de session/workspace des barrières de page. Un relevé authentifié ne contient que les pages visibles. Il retire seulement les copies affectées, dans toutes leurs générations ; les réponses tardives et les tickets d'anciens onglets ne peuvent les réintroduire. Déconnexion, retrait de membership et interdiction du cache gardent une purge sur tout leur périmètre réel. Une perte de droit ne provoque aucun renvoi automatique du travail retenu en mémoire.

Les tests vérifient les **identifiants originaux des enregistrements IndexedDB**, pas seulement un cache repeuplé après coup : archivage sans rapport et déplacement sans effet préservent sockets, éditeur et contenu stocké. Un retrait réel ferme le socket concerné sous cinq secondes dans l'essai serveur ; un second utilisateur de la même page reste connecté. Le navigateur vérifie aussi la réduction de droits, le gel réel, la réattribution et le refus de rejouer l'ancienne édition.

Avant mise à jour, synchroniser ou exporter le travail de test et fermer les anciens onglets. Appliquer `pnpm db:migrate`, compiler et redémarrer API/collab/worker/web. Aucun reset PostgreSQL. Les vieux jetons WSS de portée workspace sont refusés : recharger le front. L'upgrade IndexedDB conserve les tombstones de logout et les copies v3 dont la version correspond encore au relevé serveur ; une copie périmée est retirée. La lecture du cache attend toujours une confirmation en ligne.

Ce qui pourrait casser : ordre des verrous/deferred triggers, migration d'un ancien cache, modification du protocole WSS sans renouveler la portée, ou nouvelle route oubliant les quotas/attaques. Les futurs volumes de lignes de bases exigent de revoir le verrouillage de toutes les pages, avant dépassement de 1 000 pages.
