# Session 4e — poste partagé et politique de cache

Sur `codex/session-4-strong-auth`, après validation manuelle de 4d. Arrêt pour relecture après cette livraison ; 4f et ses benchmarks restent à faire. Le développeur créera et fusionnera la PR unique de session 4 après 4f. La description `.local/session-4e-pr.md` complète les descriptions intermédiaires conservées.

## Ce qui change

La connexion propose « Poste partagé », décoché par défaut, pour email/mot de passe et passkey. Le serveur conserve ce choix après enrôlement, vérification et rotation de session. Le premier enrôlement TOTP remplace parfois la session dans Better Auth : ses réglages sont désormais capturés avant cette suppression puis transférés. Le mode partagé efface les anciennes copies du compte et garde seulement le document en mémoire.

Le propriétaire peut interdire les copies locales à tous les membres, lui compris, avec une preuve forte récente. La règle est versionnée et auditée ; elle prime sur le choix personnel. Elle efface uniquement les copies de ce workspace. Les autres comptes et espaces restent intacts. Une confirmation permet d'annuler pour synchroniser/exporter avant un changement volontaire. Une interdiction distante s'applique sans confirmation dès sa réception et conserve le travail ouvert en mémoire.

Le risque des huit réservations occupées est explicitement inscrit dans la matrice 4f, avec la décision prévue du développeur : accepté pour le MVP auto-hébergé ; recours passkey/récupération. Cookies d'appareil de confiance avec file réservée et protection globale en amont deviennent des prérequis SaaS, encore non implémentés.

## Ce qui pourrait casser

- Il faut appliquer la migration avant de démarrer le nouveau code. La mise à niveau IndexedDB préserve le contenu autorisé ; un ancien onglet gardant une connexion ouverte peut demander d'être fermé pour la terminer.
- Une coupure réseau ou un navigateur suspendu empêche la réception immédiate d'une interdiction distante. Contrôle en ligne obligatoire avant toute nouvelle hydratation ; décisions reçues par un autre onglet appliquées dans chaque transaction locale. Les minuteurs ne promettent pas cinq secondes sur une machine suspendue.
- Sans cache, fermer/recharger un onglet hors ligne perd le travail non envoyé. La bannière l'indique ; synchroniser ou exporter avant. Une réautorisation nécessite de rouvrir la page pour reprendre le cache.
- Un stockage indisponible bloque le nettoyage et affiche une erreur ; ne pas considérer le poste comme nettoyé. Les tombstones sans contenu peuvent rester après déconnexion.
- Cette politique gère les copies de l'application. Elle ne peut empêcher une personne autorisée d'exporter volontairement le contenu, ni effacer un export déjà réalisé.

## Guide manuel pas à pas

1. `pnpm db:migrate`, `pnpm build`, puis démarrer API, worker, collab et web derrière Caddy. Les services locaux de cette livraison sont déjà redémarrés. Ouvrir `https://localhost` avec un propriétaire équipé d'un facteur fort ; garder ses moyens de secours. Les intitulés peuvent être longs : leur finition générale reste une étape distincte.
2. Vérifier que « Poste partagé » est décoché à la connexion. Se connecter normalement, ouvrir une page dans trois onglets du même navigateur. Écrire une phrase, attendre « Enregistré sur le serveur » et « Copie locale à jour ». Dans DevTools → Application → IndexedDB, `memoria-yjs-cache-v1` est maintenant en **version 2** ; `documents`/`updates` contiennent la copie. Le nom v1 est conservé pour migrer la même base.
3. Mettre le troisième onglet hors ligne via DevTools et saisir une phrase distinctive. Attendre la copie locale ; laisser cet onglet en arrière-plan. Dans une fenêtre privée ou un second navigateur, connecter le propriétaire, vérifier récemment son facteur, ouvrir « Sécurité de l'espace », décocher « Autoriser les copies locales… » puis enregistrer. Lire la confirmation ; une première fois, annuler pour vérifier que la politique reste autorisée. Refaire et confirmer.
4. Dans les onglets actifs, attendre le message « Copie locale désactivée… ». Les entrées de ce compte/workspace disparaissent de `documents` et `updates`. Réveiller l'onglet hors ligne : la phrase reste affichée en mémoire, mais saisir davantage ne recrée pas d'entrées. Réactiver le réseau ; attendre la confirmation serveur et retrouver la phrase dans les autres onglets. Le test automatique fige réellement cet onglet pour couvrir un retard plus fort que le simple arrière-plan.
5. Si vous avez un second workspace ou compte dans ce profil navigateur, vérifier que ses copies restent présentes. Réautoriser le cache au premier workspace, rouvrir la page et constater une nouvelle copie. Un ancien onglet ne réactive pas son cache tout seul.
6. Ouvrir `/connexion` dans un autre onglet du même navigateur, cocher « Poste partagé », saisir les identifiants, puis cliquer sur connexion. La confirmation avertit de l'effacement de toutes les copies de ce compte ; annuler permet de revenir aux onglets pour synchroniser/exporter. Confirmer, puis vérifier le second facteur. Refaire aussi par passkey si vous le souhaitez. La politique serveur est visible dans la réponse réseau `/api/auth/security/cache-policy` : `sharedComputer: true` après rotation.
7. Ouvrir la page dans cette session partagée. La copie est désactivée même si le workspace l'autorise. Passer hors ligne et écrire : le message demande de garder l'onglet ouvert et prévient de la perte à la fermeture. `documents`/`updates` n'accumulent rien pour ce compte. Reconnecter et attendre l'enregistrement avant de poursuivre.
8. Depuis « Mes espaces » ou « Sécurité du compte », demander puis confirmer la déconnexion et l'effacement. Réveiller les anciens onglets : ils ne doivent plus écrire de cache ni rendre une copie accessible. Les entrées de contenu du compte sont absentes ; les marqueurs techniques peuvent rester. Une nouvelle connexion sans la case réautorise une nouvelle copie si le workspace le permet.
9. Reproduire automatiquement : `pnpm test:auth:cache`, puis `pnpm test:auth:cache:browser`. Le second crée et supprime seulement ses comptes/workspace de fixture ; capture `.local/session-4e-shared.png`. Les résultats complets servent de référence, pas une annonce de test en cours.
